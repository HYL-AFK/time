# WiTime 验收测试清单

**版本**：v0.4-demo  
**日期**：2026-10-28  
**用途**：项目结项验收，全部 P0 通过即可交付

---

## 0. 测试环境

| 项目 | 要求 |
|---|---|
| 硬件 | ESP32-C3 + ASRPRO V5.0 + 24 像素灯环 + TF 卡 |
| 供电 | USB 5V ≥1A（ASRPRO 峰值电流高，供电不足会链路 OFFLINE） |
| 网络 | 2.4 GHz WiFi，可访问外网 |
| 串口 | ESP32 的 COMx（115200）、ASRPRO 的 Type-C（115200） |
| 环境 | 安静室内，距离设备 0.5~1 米说话 |

## 0.1 测试前准备

```bash
# 1. 烧录 ESP32
idf.py -p COMx flash

# 2. 确认链路（看日志出现 READY）
# I (xxxx) link: state=READY rtt=19xms ...

# 3. 清空闹钟（避免满槽干扰）
# 小爱同学 → 全部取消
```

**通过标准**：`state=READY` + `peer[ok=N]` 持续递增。

## F. 闹钟（重点）

| ID | 用例 | 步骤 | 预期 | 优先级 |
|---|---|---|---|---|
| F-01 | 三步设置 | 定闹钟 → 今天的 → 下午 → 三点三十分 | **确认句 + 读回**：「好的，已经帮你设定好闹钟了，今天下午三点三十分的时候叫你一次」 | P0 |
| F-02 | 时段正确 | 同上 | 日志 `period=2`（下午），时间 `15:30` | P0 |
| F-03 | 明天闹钟 | 定闹钟 → 明天的 → 上午 → 八点整 | 「明天上午八点整的时候叫你一次」 | P0 |
| F-04 | 每天闹钟 | 定闹钟 → 每天的 → 晚上 → 九点 | 「每天晚上九点的时候都会叫你」 | P0 |
| F-05 | 满槽提示 | 已有 2 个时设第 3 个 | 「已帮你找到两个已经设定好的闹钟…是否要全部取消？」 | P0 |
| F-06 | 响铃 | 设 2 分钟后的闹钟 | `101.mp3` + 「现在是…记得按时起床哦」 | P0 |
| F-07 | 语音停止 | 响铃时说「停止」 | 铃声立刻停 | P0 |
| F-08 | 取消流程 | 取消闹钟 → 全部取消 | 「好，我已经把闹钟全部取消」 | P0 |
| F-09 | 跨天顺延 | 设一个已过去的时间 | 自动顺延到明天，日志 `pushed-to-tomorrow` | P1 |
| F-10 | 断电保持 | 设闹钟后断电重启 | 闹钟仍在 | P0 |

**关键日志**：
```
I (xxxx) link: peer sets alarm: day=0 period=2 15:30
I (xxxx) time_service: alarm 1 set to 15:30
I (xxxx) time_service: confirm alarm: once 15:30 period=2 (8 segments)
```

**F-01 若失败，先看日志有没有 `peer sets alarm`：**
- 没有 → 识别层（说太快 / 抢话被回声闸门丢）
- 有但内容错 → 词表映射
- 有但没播 → 播报层

## J. 验收标准

### 必须全部通过（P0）

- A-01 ~ A-05（开机显示）
- B-01、B-02（配网）
- C-01、C-03（时间/日期）
- D-01（天气）
- E-01、E-02、E-03（整点报时）
- F-01 ~ F-08、F-10（闹钟核心）
- G-01 ~ G-05（计时核心）
- H-01、H-02、H-05（按键与音量）
- I-01 ~ I-04（异常恢复）

### 可接受缺陷（P1/P2）

- 5 分钟档位限制（设计约束，非缺陷）
- 闹钟需分步说（ASRPRO 能力限制）
- 弱供电下链路间歇（硬件限制）

### 结项判定

**P0 全通过 + P1 无阻塞性缺陷 = 验收通过。**
