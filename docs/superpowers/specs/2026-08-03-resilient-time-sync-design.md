# 稳定校时设计

## 目标

即使 IP 时区定位服务不可用，也不能阻止时钟获得 UTC 时间或显示可用的本地时间。

## 约束

- 现有 BluFi 手机应用不能修改。
- 手机应用不会下发固定时区。
- 首次成功校时时，默认以中国标准时间（`UTC+8`）显示。
- 继续使用已保存的 Wi-Fi、SNTP、NVS 以及后台 IP 时区定位。

## 设计

开机时，优先使用 NVS 中已保存的 UTC 偏移；若从未保存过，则先使用 `UTC+8`。IP 时区定位降级为“尽力刷新”：定位成功才更新并保存偏移，定位失败绝不能中断已经成功的 SNTP 校时。

SNTP 仍使用阿里和腾讯两个服务器，总等待窗口保持 8 秒。SNTP 成功后，时钟使用当前可用的偏移显示：本次 IP 定位得到的偏移、NVS 保存的偏移，或首次启动时的 `UTC+8` 默认值。定位错误只写入运行日志，包含供应商、ESP 错误码和 HTTP 状态码；显示直接进入正常时钟。

用户可见的校时失败只保留真正的 SNTP 失败。网络检测和 IP 定位失败仍能从运行日志排查，但不会把时钟带入失败页面。

## 验证场景

1. 没有保存时区且两个 IP 定位接口都失败：SNTP 成功后以 `UTC+8` 显示，不保存无效偏移。
2. 已保存时区且两个 IP 定位接口都失败：SNTP 成功后继续使用保存的时区显示。
3. IP 定位成功：保存并使用新偏移显示 SNTP 时间。
4. SNTP 失败：保留现有失败处理。
5. 运行日志仍记录 IP 定位失败详情，且不记录 Wi-Fi 凭据。
